# Spec：Sensor-web-page log 與警告改善（2026-10-31 草稿）

專案：`C:\Users\MyUser\Desktop\Sensor-web-page`（sensor-pc）。依據：`docs/log-inventory.md`、`docs/log-tree.md`、`docs/log-review-20261030.md`。

## 目標
讓使用者看 log、狀態卡、通知時，能分辨「發生了什麼、原因是什麼、要做什麼」，並分得出暫時失誤與真故障。

## 範圍
- 套用到所有 sensor（溫度計、測距儀、光譜儀、音訊）與電源，以及共用的「狀態變化自動 log」機制。
- 不碰：`--host`／網路綁定、遠端緊急關閉、電源或儀器的通訊協定與命令內容、韌體、CSV 欄位格式、push。

## 需求
R1 保留儀器原始資訊
- 電源回傳的警告／警報原文（含模組編號與溫度值）、代碼數值，照實寫入 server log 與 `experiment_<id>.json`。
- 測距儀錯誤碼（如 0x2003、0x2008）以數值寫入 log 與 JSON，不得顯示成 None；對照表沒有時標「未知碼 0x....」。
- 程式自己的翻譯（如 61657「溫度警告」）保留，但必須和原文並列，不能取代。
- CSV 格式不變。

R2 暫時失誤與真故障分開
- 單次或短暫的讀取失敗：記 INFO 單行、不附 traceback、不跳通知。
- 升級為真故障的條件：連續失敗達 10 次，且持續至少 5 秒。升級後才記 WARN／ERROR 並跳通知。
- 恢復時記一行，包含失敗次數與持續時間；短暫失誤另外在停止實驗時彙總成一行（次數、最長持續、錯誤碼）。

R3 去重與等級一致
- 電源每個事件保留「系統」與「電源」兩行，但兩行等級相同，依事件真實嚴重度決定。
- 預檢只記一次結果，不重複兩遍。
- Test version 這一家族（手冊編號 61704／61711／61714，互相矛盾）：預設降成 INFO、不跳通知、不顯示紅色；log 與 JSON 附手冊原文與代碼數值；不稱它為故障，也不宣稱韌體是測試版。（使用者已授權用此預設，2026-10-31）

R4 網頁文字
- 狀態卡與通知文字改為「原因＋發生了什麼＋建議做什麼」。
- 狀態卡有兩段：短現象在通知；原因與建議在卡片展開。
- 測距儀 ALARM：寫成「HEAD X 收不到反射光（ALARM）：檢查距離、角度、表面反光，或換 HEAD」；不得用「斷線」「USB 中斷」描述 ALARM。
- 「USB 可能中斷」只用於確實為通訊層錯誤的情況，並附錯誤碼。
- 61657：寫成「電源溫度警告（原文：…）」，不寫「過溫」「已過熱」，因來源模組未確認。

## 驗收
A. 靜態：專案編譯／啟動成功；既有單元測試通過；新增單元測試涵蓋 R1–R4。
B. 情境模擬（獨立的 subagent，無記憶）：
   1. 該 subagent 先拿到系統功能說明，列出盡可能多的故障情境與排列組合（至少含：測距儀 ALARM 持續／間歇、錯誤碼 0x2003→0x2008 短暫失敗、USB 真斷線、電源 61657 持續／一次性、61711／61714 連線時出現、輸出開啟中同時多感測器異常、停止時仍在失敗、模擬模式）。
   2. 用程式內建的模擬模式或注入方式實際產生這些情境，收集 log、JSON、網頁通知。
   3. 逐情境判定：log 是否讓人讀得懂原因、是否有原始資訊、等級是否合理、是否有重複、通知是否過多或遺漏。輸出矩陣表與未達標項目。
C. 不得有硬體風險：不連真電源、不送任何寫入命令。
